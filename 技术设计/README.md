# 在线合同智能审查与修订系统：技术设计

版本：V1.0，2026-10-15。状态：实施设计稿，不代表当前仓库已经完成重构或接入工程门禁。

配套需求：[需求文档](../在线合同智能审查与修订系统-需求文档.md)。需求与技术细节冲突时先修订决策记录，不在代码中静默改变业务语义。

## 设计结论

采用模块化单体业务系统、独立审查 Worker 和独立文档服务。前端使用 Vue 3 工程化结构；文档编辑器和模型服务均通过明确的适配接口接入。

本项目的业务核心是“版本—问题组—修订—复核决定”，不能绑定某个编辑器的临时修订 ID，也不能以浏览器中的正文字符串作为唯一状态。

首期只实现一个编辑器和一个模型协议适配器，不提前实现多厂商通用平台。接口服务于已知变化点，避免过度抽象。

## 不可破坏的约束

1. 原始文件与已发布版本不可变；所有修改形成新版本。
2. 自动建议不等于采纳，界面状态不等于文件已保存。
3. 后端是任务与版本的事实来源；前端和编辑器临时状态均不能替代持久记录。
4. 深度审查失败不得回退固定规则后标为模型成功。
5. 浏览器断开事件订阅不取消任务；明确取消操作才发送取消命令。
6. 所有发布、保存与复核命令验证版本，防止旧请求覆盖新版本。
7. 页面、API 路由、工作流编排文件不承载其他模块的核心实现。
8. 源文件在 CI 中执行大小和依赖门禁，不能仅依赖开发者自觉。
9. 内部思维链不进入前端和公开事件，公开分析来自结构化意见字段。
10. 复杂排版与原生修订由文档服务及 DOCX 处理层负责，不自研网页 Office 内核。

## 实施前的能力闸门

先用真实合同验证在线编辑、保存、原生修订、批注、意见定位与双向状态同步。若所选授权版本不能提供必要接口，须调整授权或范围，不能用假状态代替。

## 文档维护

- 本索引只保留导航与决策摘要，不复制各专题正文。
- 专题文档上限 250 行；超过时拆出有独立职责的新专题并更新索引。
- 重大决策使用 `docs/adr/NNNN-主题.md`，每份建议不超过 100 行，记录背景、选择、代价与替代方案。
- 每次改动只读取相关专题、模块说明、接口及目标文件，不默认加载全部仓库。
- 官方资料用于核对产品能力，项目提出的分层、阈值和流程是本项目设计，不是厂商保证。
