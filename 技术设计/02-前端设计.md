# 02 前端设计

## 1. 组件与状态边界

前端按业务 feature 组织，不按“全部组件”“全部 hooks”“全部 API”横向堆积。

```text
pages/workbench/
  WorkbenchPage.vue          # 布局及模块组合，目标 ≤150 行
  WorkbenchToolbar.vue       # 页面级命令入口
  useWorkbenchController.ts  # 协调保存、发起审查与切换版本

features/review/
  components/
    ReviewProgressDialog.vue
    ReviewProgressHeader.vue
    PublicAnalysisFeed.vue
    ReviewExecutionLog.vue
  composables/
    useReviewCommands.ts
    useReviewEvents.ts
  stores/reviewRun.store.ts
  api/review.api.ts
  types.ts
  index.ts
```

其他 feature 遵循相同结构，但不强制为无需要的目录创建空壳。

Vue 官方支持通过组件和 composable 分离 UI 与可复用有状态逻辑：[组件](https://vuejs.org/guide/essentials/component-basics)、[组合式函数](https://vuejs.org/guide/reusability/composables)。本项目额外规定以下边界。

## 2. 状态事实来源

| 状态 | 归属 | 规则 |
| --- | --- | --- |
| 当前版本、任务、复核决定 | 后端；前端 store 为缓存 | 命令成功后按服务端版本更新 |
| 文档未保存编辑 | 编辑器会话 | store 只记录 dirty、session、保存状态，不复制整篇正文 |
| 当前任务公开事件 | review store | 按 seq 去重，界面只保留有界窗口 |
| 筛选、展开、输入框草稿 | 对应组件/composable | 不放入全局大 store |
| 缩放、侧栏偏好 | 偏好 store，可持久化 | 不含合同正文、模型密钥与最终业务状态 |

使用单一事实来源，避免多个组件各自保存并回写完整合同。[Vue 状态管理说明](https://vuejs.org/guide/scaling-up/state-management.html)

禁止建立同时管理用户、编辑器、模型、导出、正文和全部任务的 `workspace.store.ts`。

## 3. 组件职责

- 展示组件只接收 props、发出明确事件，不直接调用模型服务。
- 业务组件通过 feature API/composable 发命令，不自行拼接路径和请求头。
- 页面负责排布与协调，不直接订阅底层编辑器 SDK 的全部事件。
- composable 按职责拆分；`useWorkbenchController` 不再长成第二个超大页面文件。
- 跨 feature 协作由页面或明确 workflow controller 编排，禁止隐式全局事件总线。
- 事件、计时器、订阅、编辑器实例必须在卸载时释放。

## 4. 编辑器适配器

`EditorAdapter` 表示前端与一个编辑会话交互的边界，建议提供：

```ts
interface EditorAdapter {
  mount(container: HTMLElement, session: EditorSession): Promise<void>
  flush(): Promise<SaveCheckpoint>
  locate(anchor: RevisionAnchor): Promise<LocateResult>
  execute(command: EditorCommand): Promise<CommandReceipt>
  subscribe(handler: (event: EditorEvent) => void): () => void
  getCapabilities(): EditorCapabilities
  dispose(): Promise<void>
}
```

`flush` 必须等到后端确认持久化检查点，不把 SDK 的“请求保存已发出”当成成功。SDK 没有直接能力时，由适配器调用后端创建保存请求并等待确认。

能力声明至少包括：审阅、批注、修订定位、单项接受/拒绝、批量处理、事件通知和保存检查点。只展示已验证支持的命令；不能承诺缺失接口自动降级为同等能力。

首期 `OnlyOfficeAdapter` 按 `session`、`commands`、`events`、`lifecycle` 拆文件，不能把整个 SDK 包装塞进一个文件。

## 5. 审查过程界面

- 不依赖阶段百分比制造假进度；服务端阶段完成数只是近似指标。
- 标题、取消按钮固定可见；中部滚动；日志默认收起。
- 使用显式组件 CSS 限定高度和 overflow，不依赖未经构建的动态工具类。
- 公开摘要与执行日志分开。公开摘要显示原文、风险说明和修改方向，不展示内部思维链。
- 初步摘要按 `run_id + attempt + item_id` 标识；重试后清楚区分旧轮次。
- 事件在前端批量刷新，不按每个 token 更新整个页面。
- 首期界面事件缓存最多 200 条，摘要最多显示最近 50 条；完整历史通过分页读取。超过容量显示“查看历史”，不得丢弃服务端事实。
- 断线提示“重新连接”，不把断线显示为模型失败或自动取消任务。

## 6. API 与类型

- 使用唯一 HTTP 客户端，集中处理认证、错误和请求 ID。
- 从后端契约生成类型；生成文件按模块拆分，业务代码不复制接口定义。
- 业务错误转为有意义的提示，不把服务端堆栈或原始模型回复直接弹给用户。
- 命令附带幂等键和预期版本；点击状态与服务端操作状态分别管理。
- 禁止深层 watch 整个 workspace 后自动提交全部正文与所有状态。

## 7. 样式与复用

- 建立颜色、间距、字号、层级、弹窗尺寸等设计变量。
- shared/ui 只放 Button、Dialog、Select、EmptyState 等无业务组件。
- IssueCard 留在 issues，RevisionAction 留在 revisions，不包装成万能卡片。
- 不通过全局 `header`、`aside` 等标签选择器修改业务组件。
- 组件样式使用 scoped 或明确命名空间，测试包含小视口、长文本与字体放大。

## 8. 前端门禁

执行格式检查、ESLint、TypeScript 检查、生产构建、文件大小和模块依赖检查。

关键验证：刷新恢复、任务重连、长日志布局、取消、编辑保存、侧栏收起与修订定位。验证真实生产构建，不能仅验证开发服务器。
