# 08 部署、测试与实施

## 1. 本地与生产拓扑

本地：前端开发服务、API、Worker、PostgreSQL、Redis、文档服务分别启动。可用 Docker Compose 管理依赖，浏览器实际访问地址与容器互访地址分别配置。

生产首期可在同一台服务器运行反向代理、静态前端、API、Worker、数据库、队列和文档服务，保留独立容器及数据卷。文档服务和 Worker 的 CPU/内存限制独立设置，不让一个长合同占满整台机器。

数据库和对象存储是持久事实来源；Redis 队列丢失可根据数据库任务和 outbox 重投。不能仅靠 Redis Pub/Sub 保存唯一事件历史。

## 2. 配置与外部连通

配置分为 public origin、API origin、文档服务浏览器地址、文档服务内部地址、受控文件读取地址、保存回调地址及模型能力配置。

- 浏览器能访问文档服务，文档服务能读取授权文件并回调 API。
- 容器中 localhost 不当作宿主机地址。
- 反向代理为 SSE 禁止缓冲，配置合理的读取超时；业务任务不因此绑定连接。
- 模型密钥、回调验证密钥和 JWT 配置放服务端环境或密钥设施，不放前端构建变量。
- 测试开发地址、生产域名与 HTTPS 不混用。
- 依赖版本和镜像使用经过验证的固定版本；升级走兼容样本与适配器测试，不直接跟随 latest。

## 3. 权限与文件边界

文件下载令牌绑定用户/会话、文档版本、用途和有效期。回调验证签名、会话键、generation 和业务归属。

文档回调提供的下载地址只允许已配置文档服务来源，不任意抓取外部 URL。对文件大小、类型、解压体积、下载时间及 DOCX 结构设置限制。

首期文件/页数/并发上限应由样本压测确定并配置，超过限制明确拒绝或转人工，不静默截断合同。

## 4. 备份与运维

- 文件与元数据按同一可恢复时间点备份，定期实际恢复验证。
- Worker 租约、未投递 outbox、回调失败、孤立文件和待对账命令有巡检任务。
- 健康检查分别覆盖 API、Worker、数据库、队列和文档服务连通性。
- 限制模型并发、任务排队深度和存储增长，显示可理解的繁忙状态。
- 日志通过关联 ID 排查，不默认保存全文、密钥和模型内部推理。

## 5. 测试分层

| 层级 | 重点 |
| --- | --- |
| 单元 | 状态机、预算、重试、合并、锚点、幂等、字符变化 |
| 契约 | OpenAPI、公开事件、模型 schema、编辑器适配接口 |
| 集成 | 数据库事务、outbox、队列重复投递、文件发布、回调 |
| 编辑器验证 | 原生修订、批注、定位、直接接受/拒绝、保存生命周期 |
| E2E | 上传→审查→建议版本→复核→保存→刷新→导出 |
| 文档兼容 | 在线编辑器、目标 Office/WPS 中打开实际导出文件 |
| 真实 AI 样本 | 结论差异、原文引用、无事实捏造、最小修改与覆盖 |

mock 只用于可控失败和边界测试，不能替代真实文档服务与模型验证。

## 6. 必测故障矩阵

- 网络断开、SSE 重连、API 重启、Worker 崩溃与租约接管。
- 模型鉴权失败、超时、限流、截断、格式无效、修正重试耗尽。
- 编辑器回调重复、延迟、乱序、下载失败、过期会话和旧版本覆盖尝试。
- 文件已上传但事务失败、事务已提交但事件通知丢失。
- 审查期间人工修改 head，发布前发生取消，取消后模型才返回。
- 同条款多个角度、跨段修改、重复原文、表格及合并单元格。
- 原文含空白字段、模型扩展待确认占位符、伪造金额或税率。
- 同一问题组部分接受，编辑器直接操作，以及重置遇到人工修改。
- 长日志、小窗口、字体放大、键盘取消及页面刷新。

## 7. 性能与资源验收

设定短、中、长合同样本及并发档位，记录模型首个公开摘要、总耗时、保存回调、接口响应、内存峰值、事件数量和文件体积。

性能目标由首轮压测确认并写入部署验收记录，不在缺少机器规格与样本时承诺固定吞吐量。

同时验证事件按条追加、前端缓存有界、长文本不反复跨组件复制、流式解析不阻塞主线程，以及模型上下文预算确实生效。

## 8. 实施阶段与退出条件

### M0：文档服务能力验证

交付可运行 POC、合同样本结果、授权/资源清单。必须验证原生修订、批注、定位、保存和双向状态同步。未通过前不做完整漂亮页面来掩盖核心能力不足。

### M1：工程脚手架与门禁

建立目标目录、依赖组装、类型契约、主题变量、模块 README、文件大小和依赖检查。CI 在脚手架阶段就运行，后续代码不得绕过。

### M2：文档业务闭环

完成上传、不可变版本、编辑会话、保存检查点、回调幂等、版本冲突和导出。先验证人工原生修订，再接 AI。

### M3：审查与修订闭环

实现任务持久化、Worker、事件重连、分片上下文、有限重试、校验、问题合并、修订计划与建议版本发布。

### M4：复核一致性

实现侧栏与编辑器双向处理、保存后确认、部分处理、对账、历史恢复及完成复核校验。

### M5：体验和稳定性验收

通过真实模型、文档兼容、故障矩阵、长日志布局、取消与恢复测试，记录仍存在的兼容限制。

## 9. 旧项目迁移

- 新工程与旧入口隔离，可先并行运行，不在超大 HTML 上继续无边界追加。
- 保留原始 DOCX、审查输入快照、意见和处理记录，使用明确迁移 schema。
- 旧网页 Diff 不能直接宣称已是 Word 原生修订；转换需重新校验和用户确认。
- 旧接口通过短期薄兼容层接入，设移除条件，不复制业务实现。
- 每迁移一个用例就补对应端到端验证，确认数据与导出一致后切换入口。
- 旧超大文件先冻结增长，再按功能退休；禁止新旧两套状态长期互相回写。

## 10. 首期交付物

可启动部署配置、模块化源代码、迁移脚本、自动门禁、接口契约、编辑器能力报告、真实样本验收记录、运维与恢复手册。

交付说明须区分已完成、仅通过 mock、已在真实服务验证、待授权或待验证事项。
