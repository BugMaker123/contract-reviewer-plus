# 05 AI 与上下文

## 1. 模型适配层

业务流水线依赖 `ModelGateway`，不依赖某个厂商 SDK 或 LangGraph 内部状态。

```text
generate(request, deadline, cancellation) → StructuredResult
stream(request, deadline, cancellation) → PublicResultChunk
```

请求包含模型配置引用、prompt 版本、结构化上下文、输出 schema 和调用 ID。密钥由后端解析，不能出现在业务事件或队列消息中。

厂商适配器负责请求参数、token 统计、流式块、错误及连接释放。业务层负责重试决策、输出校验和最终接受结果；不能在 SDK 内重试 3 次、外层再重试 3 次造成次数相乘。

## 2. 提示词拆分

```text
reviews/prompts/
  policy.md                 # 共同边界与输入信任规则
  analyze_clauses.md
  consolidate_issues.md
  rewrite_clause.md
  repair_output.md
  summarize_result.md
```

提示词有版本号与稳定变量 schema，单个模板不超过 120 行。修改提示词需跑对应语义回归，不把长 prompt 塞进 Python f-string。

## 3. 输入结构化

提取 DOCX 为层次化块：章节、段落、表格、单元格、条款编号及原文引用。给块分配稳定于当前版本的 ID、结构路径和内容 hash。

保留原文，生成摘要不覆盖原文。原生修订已有插入/删除时，先明确审查采用“当前显示最终文本”还是其他视图，并记录选择，不能混用两个基线。

引用与编辑范围必须可回到版本和块 ID，模型给出的文本不是新的原文事实。

## 4. Token 与长合同预算

调用前计算：`可用输入 = 模型上下文上限 - 输出预算 - 系统提示 - 修正反馈 - 安全余量`。

- 模型上限来自受控能力配置，不把所有模型当成同一窗口。
- 有可靠 tokenizer 时使用实际 token；只能估算时提高余量并记录估算方式。
- 为修订输出保留足够空间，不能用全文填满输入后期待返回长篇改写。
- 分片按条款层次和 token 预算，不按固定字符数直接截断。
- 相邻定义、引用条款和必要上下文按依赖补入，不重复发送整份文档。
- 超大单条款需再按结构拆分，记录父子范围，不强行裁掉尾部。

每次调用保存输入块清单、prompt 版本、token 预算和覆盖范围，不保存密钥。

## 5. 分层审查与覆盖

1. 提取全局事实：当事人、角色、日期、金额、定义和条款引用，事实须附原文出处。
2. 以条款组进行局部审查，输入相关事实与必要交叉引用。
3. 进行跨条款一致性检查，核对付款、开票、解除、责任及定义冲突。
4. 按实际源范围合并问题，保留各风险点与引用。
5. 按条款生成最小修改并验证，再组装修订计划。

维护 coverage manifest：每个源块标记未处理、处理中、已分析、失败或需人工核验。未处理块存在时，不得宣称全文完成。

并行度有界，按部署配置和模型限流设置。各分片共享整次任务 deadline、调用预算和取消信号，不能无限扩展重试成本。

## 6. 模型输出契约

问题组至少包含：源块引用、原文锚点、风险级别、公开风险说明、依据及修改方向。

RevisionPlan 与问题解释分开，不能从一大段自然语言里猜测实际替换操作。没有依据时明确标注未提供，不补造法规、金额、税率或损失。

缺失事实留在意见里；正文保留已有空白。不得批量新增待确认表单，不把某行业税率硬套到所有合同。

## 7. 校验顺序

传输完整性 → JSON/schema → 引用范围 → 原文匹配 → 重复与重叠 → 事实保持 → 改写是否必要 → 计划可执行性 → 生成文档复核。

允许补齐缺失 ID 等非语义元数据，不允许补造缺失风险结论。schema 修复与语义校验分开实现，不能捕获所有异常后返回空 issues 冒充没有风险。

校验器返回结构化 code、字段路径和公开说明，供模型修正及界面展示。

## 8. 有限反馈重试

首期默认最大重试 3 次，即首次加 3 次。明确区别 attempt 和 retry，不把 3 次重试显示为 3 次总请求。

- 传输错误采用有限退避；鉴权和无效地址等错误直接结束。
- 格式、遗漏、占位符及冲突错误，将校验反馈和相关原文交给模型修正。
- 每次修正只保留原始任务、相关输入、最近失败结果及必要反馈，不把全部历史不断拼接。
- 反馈与失败输出共用 token 预算；超出时提取字段级错误，不能任意截断原文事实。
- 重试不能重置全局 deadline 或调用费用上限。
- 修正成功后仍须重新校验，不能因为是第二次回复就跳过。

这是有限的“生成—观察校验—修正”循环，不依赖或展示模型内部推理。首期不引入任意工具执行代理。

## 9. 流式公开摘要

只从允许公开的结构化意见字段提取摘要。完整单项对象到达即可展示，标记 provisional；最终 schema 与原文验证通过前不发布为最终结果。

- 不订阅或转发 `reasoning_content` 等内部推理字段。
- 不把任意半截 JSON、原始 token 和模型额外文本直接插入页面。
- 每项摘要有 run、attempt、item_id；重复事件可去重。
- 重试后保留审计历史，当前摘要区只显示有效轮次。
- 前端收到摘要不表示建议文档已保存。

流式解析器、公开字段投影、schema 校验、重试策略和 SDK 传输各自独立成文件。

## 10. 上下文产物复用

结构提取和全局事实按源版本 hash 缓存。缓存键包含提取器、prompt、schema、模型标识及审查条件，不复用不同立场的意见。

缓存不可跨用户权限边界泄露内容；保存的是产物引用，读取时仍验证权限。业务背景变化时，受影响分析必须失效。

## 11. 评估

保留独立样本集验证不同合同确实产生不同结论，重点关注引用准确、无事实捏造、最小改写、无占位符膨胀、跨条款一致性和未分析范围提示。

mock 用于验证协议与失败分支；真实模型能力需要经授权的样本测试。mock 全绿不能作为真实 AI 审查质量已达标的证据。
