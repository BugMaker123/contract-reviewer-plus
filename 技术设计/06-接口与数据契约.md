# 06 接口与数据契约

以下是目标契约草案，不表示当前旧 API 已按此实现。实施时统一生成 OpenAPI 与前端类型，协议变更纳入版本管理。

## 1. 关键对象

| 对象 | 关键字段 |
| --- | --- |
| Contract | id、title、head_version_id、latest_review_run_id、revision |
| DocumentVersion | id、document_id、parent_id、kind、object_key、content_hash、created_by |
| EditorSession | id、base_version_id、provider、document_key、generation、save_checkpoint |
| SaveRequest | id、session_id、expected_generation、status、confirmed_version_id |
| ReviewRun | id、input_version_id、condition_hash、status、deadline、execution_epoch |
| IssueGroup | id、run_id、anchors、severity、risk_points、public_analysis |
| RevisionOperation | id、plan_id、issue_group_id、kind、anchor、expected_text、replacement |
| RevisionBinding | id、operation_id、document_version_id、provider_ref、fingerprint |
| DecisionCommand | id、expected_version_id、operation_ids、action、status、confirmed_version_id |
| ReviewEvent | run_id、seq、type、time、attempt、public_payload |
| ExportJob | id、source_version_id、kind、status、artifact_id |

对象 ID、厂商修订 ID 与段落序号不能互相替代。文档正文和原始文件不放进任务列表响应。

## 2. 关键 API

| 方法与路径 | 语义 |
| --- | --- |
| POST /api/contracts | 上传或创建任务，返回合同与原始版本 |
| GET /api/contracts/{id} | 合同摘要、当前版本及审查指针 |
| GET /api/contracts/{id}/versions | 版本分页列表 |
| POST /api/editor-sessions | 基于保存版本创建受控编辑会话 |
| POST /api/editor-sessions/{id}/save-requests | 创建保存检查点请求 |
| GET /api/save-requests/{id} | 查询真正保存结果 |
| POST /api/editor-callbacks/{provider} | 厂商回调，由独立适配器校验和转换 |
| POST /api/review-runs | 绑定版本创建任务，返回 202 和 task ID |
| GET /api/review-runs/{id} | 状态、覆盖范围、结果与产物引用 |
| GET /api/review-runs/{id}/events | SSE 订阅，支持游标恢复 |
| POST /api/review-runs/{id}/cancel | 请求取消，重复调用幂等 |
| GET /api/review-runs/{id}/issue-groups | 问题组分页 |
| POST /api/decision-commands | 对明确版本和修订执行接受、拒绝等命令 |
| GET /api/decision-commands/{id} | 查询执行、待保存与确认状态 |
| POST /api/issue-groups/{id}/followups | 针对该次版本的意见追问 |
| POST /api/contracts/{id}/verification | 校验并完成复核 |
| POST /api/exports | 绑定版本生成导出副本 |
| GET /api/exports/{id} | 状态及受控下载地址 |

异步命令返回“已受理”不代表“已完成”。长操作有独立查询接口，不要求客户端一直保持同一个请求。

## 3. 命令约束

会产生状态变化的命令使用 `Idempotency-Key`，正文携带 expected_version_id 或 expected_revision。

- 同一用户、同一操作、同一幂等键重复请求返回同一命令结果。
- 相同幂等键对应不同参数返回冲突，不执行第二份不同操作。
- 版本不符返回 409，并附当前版本与可恢复动作。
- 权限检查先于读取合同内容和执行厂商操作。

## 4. 事件格式

```json
{
  "run_id": "run_123",
  "seq": 42,
  "type": "review.analysis_provisional",
  "time": "2026-10-15T08:00:00Z",
  "attempt": 1,
  "payload": {
    "item_id": "draft_7",
    "clause_id": "clause_4_3",
    "title": "付款期限不明确",
    "evidence": "对应的实际原文引用",
    "public_analysis": "可供用户阅读的风险说明",
    "proposal": "公开修改方向",
    "provisional": true
  }
}
```

SSE 使用 `id: seq` 与 `event: type`。客户端通过 Last-Event-ID 或显式游标恢复，按 seq 去重。订阅建立时先读取缺失事件再进入实时推送，避免切换窗口丢事件。

建议事件类型：stage_started、stage_completed、analysis_provisional、retry_scheduled、coverage_updated、artifact_saved、succeeded、failed、cancelled。

heartbeat 不使用持久 seq，不作为业务进度。事件保留期到期时明确返回快照及新的恢复游标，不让客户端无限重连旧游标。

## 5. 公共错误

```json
{
  "error": {
    "code": "DOCUMENT_VERSION_CONFLICT",
    "message": "文档已产生新版本，请先核对后重试",
    "request_id": "request_123",
    "retryable": false,
    "details": {"current_version_id": "v8"}
  }
}
```

错误码至少区分鉴权、权限、版本冲突、锚点歧义、保存未确认、编辑器能力不足、模型连接、格式校验、改写校验、重试耗尽、取消及 deadline 超时。

retryable 只是当前错误属性，是否重试还需检查次数和剩余时间。details 不包含密钥、堆栈或内部思维链。

## 6. 契约兼容

- 新增可选字段通常可兼容；删除字段、改变状态语义、改变 ID 范围需要显式迁移。
- 事件消费者忽略未知可选字段，但未知关键终态不能擅自当作成功。
- 对旧 API 保留薄兼容层，不将旧处理逻辑复制进新模块。
- 类型生成文件单独目录和生成命令，业务代码只引用，不手工修补生成结果。
- 接口契约测试验证后端、前端适配器与编辑器回调之间的边界。
