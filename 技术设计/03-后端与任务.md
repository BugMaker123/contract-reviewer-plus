# 03 后端与任务

## 1. 路由与用例

路由只完成身份验证、请求校验、调用用例及结果转换。单个路由不直接执行模型重试、修改 DOCX 或处理多阶段事务。

按业务建立路由文件：`review_runs.py`、`editor_sessions.py`、`document_versions.py`、`issue_decisions.py`、`exports.py`。API 入口文件只注册路由与生命周期。

典型用例：`StartReview`、`CancelReview`、`CreateEditorSession`、`PersistEditorSave`、`ApplyDecision`、`PublishReviewResult`、`CompleteVerification`、`CreateExport`。

每个用例声明输入、输出、权限、预期版本、幂等范围与失败结果。不要使用接收任意 dict 的万能 service。

## 2. 审查任务模型

状态：`queued → running → succeeded`，并可进入 `failed`、`cancel_requested → cancelled` 或 `timed_out`。

`succeeded` 表示结果经过校验并发布到明确版本；有未能改写的条款时，结果必须附有覆盖与降级说明，不能把部分成果描述成全部完成。

`failed`、`cancelled`、`timed_out` 不改变上一版成功结果指针。

## 3. 启动与投递

1. 校验当前版本已保存，创建不可变审查输入快照。
2. 同一数据库事务内创建任务及 outbox 待投递记录。
3. 投递器将任务 ID 交给队列，投递失败可重试。
4. Worker 获取执行租约，再进入流水线。
5. Worker 每个阶段保存检查点、事件、产物引用和租约心跳。

队列按“至少一次”投递设计；同一消息重复消费不得重复创建建议版本。数据库唯一键和阶段幂等键是最后防线。

## 4. Worker 与恢复

- Worker 只接收任务 ID，不把整篇合同和密钥序列化进队列消息。
- 执行租约使用 `owner + lease_expires_at + execution_epoch`，过期后可接管。
- 接管执行必须使用新的 epoch；旧 Worker 即使恢复响应也不能发布结果。
- 阶段结果保存后才推进检查点；恢复时复用已校验产物。
- 模型请求无法保证网络级 exactly-once；重发前检查已落盘结果与调用记录，显式记录可能重复计费。
- 不能依赖 Worker 内存中的列表保存唯一进度。

## 5. 流水线边界

```text
准备版本 → 提取结构 → 构造上下文 → 条款分析
    → 原文与格式校验 → 合并问题组 → 统一改写
    → 修订计划校验 → 生成建议文档 → 发布结果
```

每一步是独立模块，接收有类型的输入并返回产物引用与结果。大文本和 DOCX 不通过每层复制传递，优先传版本 ID、块 ID 和受控读取接口。

编排器只负责顺序、有限并行、检查点、预算、取消与错误路由。文档业务写入统一经过 documents/revisions 用例。

## 6. 任务与事件分离

`POST /review-runs` 创建任务并返回 202；`GET /review-runs/{id}/events` 仅订阅事件。

- SSE 断开：停止订阅，任务继续。
- 用户点击取消：发送明确取消命令。
- 前端刷新：查询任务状态，用事件游标恢复订阅。
- API 进程重启：Worker 继续，事件可从数据库重新读取。

不得再把整个审查任务放进一次 StreamingResponse 生成器的生命周期。

## 7. 取消与时限

- 取消用例将 `cancel_requested` 持久化并发送通知。
- Worker 在调用前、分片间、重试前、产物写入前和发布事务内检查取消。
- 模型适配器在允许时关闭连接；不能终止的远端请求即使后来返回也不得发布结果。
- 取消确认必须说明“已停止发布结果”与“外部请求已终止”是否都已达到，不承诺无法保证的立即停止计费。
- 使用全局 deadline；各阶段和重试共享剩余预算。
- 超时或取消后不等待未知时长的线程收尾才更新界面。

## 8. 事件持久化与性能

- 每个任务使用递增 `seq`，数据库对 `(run_id, seq)` 唯一约束。
- 阶段变更、发现摘要、重试、失败与最终发布属于持久事件。
- 网络 heartbeat 是临时事件，不反复写数据库，也不污染业务历史。
- 不在每个事件到达时重写整个 trace 数组；按记录追加并分页。
- 只有受校验的公开字段进入事件；token 原文和内部推理不进入公开事件。
- 完成状态与完成事件在同一发布事务中提交，避免“页面显示完成但结果不存在”。

## 9. 事务与集成消息

数据库事务只覆盖本地记录，不宣称能够同时原子提交编辑器、对象存储和模型服务。

外部操作采用命令记录、幂等键、outbox、保存确认和对账任务形成可恢复流程。需要补偿时保留失败状态，不用删除历史来伪装成功。

## 10. 可观察性

日志携带 `request_id`、`run_id`、`version_id`、`command_id`、`attempt`、`execution_epoch`，不得包含 API Key 或完整原始模型响应。

指标至少包括任务等待时间、模型首个公开摘要耗时、审查耗时、重试次数、保存回调耗时、版本冲突、事件积压和取消确认耗时。

新错误必须具有稳定 code、用户提示和运维排查路径。不得全部归类成“请更换模型”。
